# Silicon Traveler

A virtual photographer's journey around the world on foot, generated by AI.

## Overview

This application simulates a photographer walking around the world from Oleiros, Spain, heading east. Each day (18:00-20:00), it automatically:
- Calculates the next route point 15-20km east, prioritizing cities
- Researches the location using web APIs
- Generates image and narrative prompts with GPT-4
- Creates a photographic image with DALL-E 3
- Publishes the photo to a gallery website

The system maintains a buffer of 10 pre-generated photos and displays them in a Magnum Journal-style gallery.

## Architecture

- **Monorepo**: TypeScript packages organized by domain
- **Hexagonal Architecture**: Each module follows domain/application/ports/adapters structure
- **Database**: MariaDB 11 without ORM (direct SQL with parameterized queries)
- **Stack**: Node.js, TypeScript, pnpm workspaces

### Modules

- `journey` - Journey management (origin, current position, heading)
- `route` - Route calculation, city finding, geocoding (Overpass, Nominatim)
- `research` - Web research (Brave Search API)
- `content` - LLM content generation (GPT-4)
- `image` - Image generation (DALL-E 3) and thumbnail creation
- `storage` - Abstract file storage (local/cloud)
- `photo` - Photo publishing and management
- `shared` - Database pool, geographic utilities, shared types

### Applications

- `cli` - Command-line tools (migrations, journey initialization)
- `scheduler` - Cron jobs (generator every 6h, publisher daily 18-20h)
- `api` - REST API server
- `web` - Next.js frontend (daily journal & archive pages)

## Requirements

- Docker and Docker Compose v2.0+
- Node.js 20+ (solo si ejecutas fuera de Docker)
- pnpm 9.12.0+ (solo si ejecutas fuera de Docker)

## Getting Started

### 1. Setup Environment

```bash
# Copy environment template and add your API keys
cp .env.example .env
# Edit .env and add:
# DB_ROOT_PASSWORD=change-me
# DB_PASSWORD=change-me
# DB_HOST=mariadb (for Docker; use localhost if running locally)
# API_KEY=change-me
# CORS_ORIGINS=http://localhost:3001
# OPENAI_API_KEY=sk-proj-...
# BRAVE_SEARCH_API_KEY=BSA...
```

### 2. Build and Start Services

```bash
# Build and start core services (MariaDB + API + Web + app shell)
docker compose up -d

# Check services are healthy
docker compose ps

# First boot installs workspace dependencies inside the app container
docker compose logs -f app
```

### 2a. Dev Compose (defaults included)

If you want quick local defaults without editing `.env`, use the dev compose file:

```bash
docker compose -f docker-compose.dev.yml up -d
```

This uses dev-only credentials and API key values. For real API calls, set `OPENAI_API_KEY` and `BRAVE_SEARCH_API_KEY` in `.env` and use the main `docker-compose.yml`.

### 3. Run Migrations

```bash
# Execute migrations to create database schema
docker compose exec app pnpm --filter @silicon-traveler/cli migrate
```

### 4. Initialize Journey

```bash
# Create initial journey from Oleiros with 10 route points
docker compose exec app pnpm --filter @silicon-traveler/cli init-journey

# This creates:
# - Journey ID 1 (from Oleiros heading east)
# - 10 route points with city enrichment (OSM + Nominatim)
# - Status: 'pending' (ready for Scheduler to process)
```

### 5. Start Applications

```bash
# API + Web start automatically with docker compose up.
# Enable Scheduler explicitly (requires API keys):
docker compose --profile scheduler up -d scheduler

# Test endpoints
curl http://localhost:3000/health
curl -H "Authorization: Bearer $API_KEY" http://localhost:3000/api/journey/stats

# Open browser
http://localhost:3001        # Web app homepage (daily journal)
http://localhost:3001/archive # Archive page (photo grid)
```

### 4. Test Database Connection

```bash
# Create a test script
cat > scripts/test-db.js << 'EOF'
const { pool, healthCheck } = require('../packages/shared/dist/index.js');

async function test() {
  console.log('Testing database connection...');
  const healthy = await healthCheck();
  
  if (healthy) {
    console.log('✓ Database connection successful!');
    
    // Test query
    const conn = await pool.getConnection();
    const result = await conn.query('SHOW TABLES');
    console.log('Tables:', result.map(r => Object.values(r)[0]));
    conn.release();
  } else {
    console.log('✗ Database connection failed');
  }
  
  await pool.end();
}

test().catch(console.error);
EOF

# Run test inside container
./scripts/docker-run.sh node scripts/test-db.js
```

### Migrations

Migrations are versioned SQL files in `migrations/` directory. Format: `YYYYMMDDHHMMSS_description.sql`

Apply migrations:
```bash
./scripts/docker-run.sh node scripts/run-migrations.js
```

Reset database (drops all tables):
```bash
./scripts/docker-run.sh node scripts/reset-db.js
```

### Schema

#### journey
Stores the single around-the-world journey.
- Fields: `id`, `name`, `description`, `origin_point`, `current_point`, `heading`, `created_at`
- Indexes: Spatial index on POINT columns

#### route_points
Stores all route waypoints with processing status.
- Fields: `id`, `journey_id`, `sequence`, `place_name`, `coordinates`, `country`, `region`, `is_ferry_crossing`, `distance_from_previous`, `osm_data`, `research_summary`, `image_prompt`, `narrative_prompt`, `camera_metadata`, `status`, `error_message`, `image_path`, `thumbnail_path`, `created_at`, `published_at`, `updated_at`
- Status enum: `pending` → `researched` → `content_generated` → `image_ready` → `published` (or `failed`)
- Indexes: `status`, `sequence`, foreign key to `journey`

#### photos
Stores published photos (denormalized for fast queries).
- Fields: `id`, `journey_id`, `route_point_id`, `image_url`, `grid_thumbnail_url`, `hero_thumbnail_url`, `narrative`, `camera`, `lens`, `iso`, `shutter_speed`, `aperture`, `revised_prompt`, `published_at`, `created_at`
- Indexes: `journey_id`, `route_point_id`, `published_at`

See [ADR 002: Database Design](.adr/002-database-design.md) for complete schema documentation.
